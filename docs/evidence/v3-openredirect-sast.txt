NOTE ON THE FIX
  The endpoint redirected to "redirect:" + the raw url request parameter, so
  ?url=https://evil.example sent the victim off-site. The fix uses an allowlist:
  only a relative path rooted in the application is permitted (no scheme, no host,
  not "//host" or "/\host"); anything else falls back to a safe local page. The
  destination is rebuilt from the parsed URI path rather than the raw parameter,
  so the tainted value never reaches the redirect sink - which is why the taint
  finding clears. An allowlist is used deliberately rather than a blocklist of
  "http://", which attackers bypass with //host, backslashes or scheme tricks;
  the regression test pins those bypass variants.
