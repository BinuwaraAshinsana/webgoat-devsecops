NOTE ON THE FIX
  A first attempt added only a canonical-path containment check AFTER the file was
  built from the raw parameter. That blocked the exploit at runtime (the regression
  test passes) but Semgrep still reported the finding, because the tainted value
  still reached the new File(...) sink and the taint rule does not recognise the
  later canonical check as a sanitiser. The fix was strengthened to strip the
  directory component from the input with FilenameUtils.getName() BEFORE building
  the path (OWASP's primary control for path traversal), so the sanitised value is
  what reaches the sink. This both clears the SAST finding and is a stronger fix;
  the canonical check is retained as defence in depth.
